# ResourcePack — developer notes

Functional reference for working in this repository. User-facing description, play links,
download and credits live in `README.md`; licensing terms live in `LICENSE`.

## What this is

A static Minecraft resource pack: `pack.mcmeta` + `pack.png` + `assets/**` + version
overlay directories (`format_*/`). There is no compile step. One pack targets every Java
release from **1.21.8 to 26.3**. Resource pack formats, read from each client jar's
`version.json`:

| Release | Format |
|---|---|
| 1.21.7–1.21.8 | 64 (the last format without a minor version) |
| 1.21.9–1.21.10 | 69.0 |
| 1.21.11 | 75.0 |
| 26.1–26.1.2 | 84.0 |
| 26.2 | 88.0 |
| 26.3 | 97.1 |

`pack.mcmeta` declares `min_format` `[64, 0]` and `max_format` `97` (a bare integer means
every minor version of 97). Because the range still reaches format 64, the 1.21.9+ loader
also requires the old fields, and 1.21.8 reads only those: `pack_format` 64 (inside the
range) and `supported_formats` `[64, 64]` (it must start at the `min_format` major and end
at either the `max_format` major or 64). When a new release ships, read its format from the
client jar, check its pack format changes (minecraft.wiki "Pack format") against the vanilla
files this pack overrides, then raise `max_format`. A client outside the range lists the
pack as made for another version.

Overlay entries follow the same rules: while any entry reaches format 64, every entry needs
`formats` (old clients) as well as `min_format` / `max_format` (new clients); directory
names are `[a-z0-9_.-]`. `tools/verify/pack.sh` checks all of this. PackSquash drops overlay
directories unless they are force-included, so `squash-release.yml` copies `format_*/**`
as-is (releases up to ResourcePack-v171 shipped without `format_64/`); a new overlay
directory must match that glob.

Overlays:

- `format_64/` (1.21.7–1.21.8 only): `minecraft:post_effect/blur.json`, the menu and dialog
  background blur. The base copy (identical to vanilla from 1.21.9 to 26.3 apart from the
  radius) uses the `core/screenquad` vertex shader, 1.21.7–1.21.8 use `post/blur`. Both
  copies pin every pass's `Radius` to 4.0, which overrides the player's Menu Background Blur
  slider (vanilla only uses the slider when `Radius` is 0). At 0 the slider still turns the
  blur off, because the client never runs the pass. Change both copies together.

Version notes for the base:

- The gun viewmodel core shader (see below) only applies on 1.21.8–1.21.11; on 26.x it is
  inert.
- From 1.21.11 (format 73) item textures live in their own `items` atlas (`item/` folders of
  every namespace) and block textures in `blocks` (`block/` folders). An item model whose
  quads use both atlases fails to bake (the whole item shows as missing), and a blockstate
  model may not use an `item/` texture. Textures outside `item/` and `block/` are in no model
  atlas on any version.

`pack.zip` is a build artifact. It is gitignored and must not be committed; the published
zip is built by CI (see below).

## Build and install

`build.sh` is a local, gitignored helper — it is not part of the published repository. It
zips `pack.mcmeta`, `pack.png` and `assets/**` (it must also include the `format_*/` overlay
directories, or 1.21.8 gets the 1.21.9+ blur) with fixed 1980-01-01 timestamps so
repeated builds are byte-identical, then installs the result as `SovereignMC.zip`:

```bash
./build.sh                                   # build + install into Lunar profile "smc"
./build.sh --no-install                      # build only
./build.sh --dest ~/.minecraft/resourcepacks # additional install folder
LUNAR_RESOURCEPACKS=/path ./build.sh         # replace the default install folder
```

The installed file keeps the name `SovereignMC.zip` because each client's `options.txt`
refers to `file/SovereignMC.zip`. The local output is `pack.zip` at the repo root.

## Verification

```bash
tools/verify/pack.sh                     # bash + jq; this is what CI runs
python3 tools/verify/argentum_refs.py    # python3 + Pillow; extra Argentum checks
```

`tools/verify/pack.sh` exits 1 on:

- invalid resource locations (anything outside `a-z 0-9 _ . - /`);
- unresolved `argentum:` parent, model or texture references;
- Argentum texture references outside a folder listed in `TEXTURE_CATEGORIES`;
- unparseable JSON, or a missing/invalid `pack.mcmeta`;
- `pack.mcmeta` format fields that break the 1.21.9+ loader or 1.21.8 (missing
  `min_format`/`max_format`, `supported_formats`/`pack_format`/overlay `formats` out of step
  with them while format 64 is supported), or an overlay whose directory has no `assets/`.

It warns on flat `item/x` / `block/x` references, allowlisted machine model refs and PNGs
that no JSON references. It only walks `assets/argentum/**/*.json`, so a green run does
not validate texture/model references in the other namespaces.

`tools/verify/argentum_refs.py` mirrors the same checks without jq and adds the 16×16 RGBA
tile audit, the item ids StructuresRevamped resolves (`TARGET_IDS`) and an
unreferenced-PNG check. Keep both green before committing.

## CI and releases

- `ci.yml` — on every push and pull request, runs `tools/verify/pack.sh`.
- `squash-release.yml` — on a push to `main` that changes `assets/**`, `bbmodels/**`,
  `pack.mcmeta` or the BetterModel generator: sets up Java 25, runs
  `tools/generate/bettermodel/generate.sh`, verifies, runs PackSquash over the repo root,
  writes `pack.zip` plus its SHA-1, and publishes/updates the latest release as tag
  `ResourcePack-v<run_number>`. Branch pushes only, by design: publishing from a tag would
  rebuild the old tree and overwrite "latest".
  The gun data textures (`assets/weapons/textures/item/objmc/*.png`) are exempt from
  PackSquash colour quantization and alpha optimizations; any other texture the shaders
  decode with texelFetch needs the same per-file override.
- `discord.yml` — posts each commit to `DISCORD_WEBHOOK`. Add `[nodiscord]` to the commit
  message to skip a commit.

Releases are the distribution channel; never commit `pack.zip`.

## Adding content

1. Item definitions use the 1.21.4+ format: `assets/<ns>/items/<id>.json` points at
   `assets/<ns>/models/item/<id>.json`, whose `textures` point at
   `assets/<ns>/textures/...`. Vanilla item overrides live in `assets/minecraft/items/`.
2. `assets/minecraft/items/feather.json` dispatches guns and magazines on
   `minecraft:custom_model_data`: thresholds `10`–`32` map to `weapons:item/*` gun models,
   `1000001`–`1000006` to `weapons:ammo/*` magazines. `assets/minecraft/items/stick.json`
   dispatches torpedoes at thresholds `100`, `101`, `102`. The server plugin must use the
   same numbers; renumbering is a coordinated change with the plugin.
3. Paths must be valid resource locations: lowercase `a-z 0-9 _ . - /` only, no spaces or
   uppercase.
4. Argentum textures must stay inside the category folders declared in
   `TEXTURE_CATEGORIES` in `tools/verify/pack.sh`. To add a category, update that list and
   the mapping tables in `tools/migrate/textures.ps1` first.
5. Texture file names are stable. Item models and plugins bind `argentum:<id>`; moving a
   texture means updating every referencing JSON's `textures.*` value in the same commit.
6. Item icons are 16×16 RGBA with a transparent background. Argentum block tiles are
   16×16 RGBA and fully opaque (enforced by the Python verifier for its target ids).

Argentum item texture categories (`assets/argentum/textures/`):

## Sound event names

Sound event names in the `sounds.json` files are the contract with the plugins:

- `assets/minecraft/sounds.json` — `bd.*` maps to `minecraft:custom/*.ogg` for
  BigDoors/AnimatedArchitecture; `turret.servo_*`, `shoot.*` and `torp_*` map to `sov:*`;
  `radar_scan` / `radar_detected` map to `minecraft:radar_*`.
- `assets/weapons/sounds.json` — `*.fire` events and `generic.hitmarker` map to
  `weapons:*` files.
- `assets/planechase/sounds.json` — `cockpit.*` callouts map to
  `planechase:cockpit/*`, with subtitles in `assets/planechase/lang/`.

Renaming an event, file or namespace breaks the calling plugin even though the pack still
loads. `assets/sov/` follows the same rule.

## `assets/minecraft/lang/en_us.json`

The keybind keys (`key.freecam.toggle`, `key.wurst.zoom`, `key.meteor-client.open-gui`,
etc.) are deliberately replaced with opaque `opec-*` strings. This is anti-cheat text, not
a broken translation — do not restore the real names.

## Gun viewmodel core shader

`assets/minecraft/shaders/core/rendertype_item_entity_translucent_cull.{vsh,fsh}` override the
vanilla item shader (same body in 1.21.8–1.21.11 apart from `#version`; the files use 330 and
import only vanilla includes). 26.1 removed this pipeline (items render through `core/item`,
and 26.3 switched shader includes from `#moj_import` to `#include`), so on 26.x the files are
inert and guns draw their plain item model in first person. A 26.x port needs a new hand
test too: `sgvmIsHand` matches the hand projection's fixed 0.05–100 depth range, while 26.x
draws the hand with the world far plane. They draw the first-person gun viewmodels: an "sgvm" model
(`weapons:item/objmc/<gun>`, texture `weapons:item/objmc/<gun>`) is a list of dummy quads whose
real camera-space positions, per-bone matrices per tick and texture live in its data texture.
Derived from objmc (MIT, `LICENSE-OBJMC`). Every other item renders exactly like vanilla.

- Generated by the gun scripts (`gunlib.write` -> `tools/generate/guns/viewmodel_bake.py`), which
  also rewrite the gun's `feather.json` entry: `firstperson_righthand` -> the sgvm model alone
  (`minecraft:model` with a `tints` list, below), `firstperson_lefthand` -> empty, everything else ->
  the item model. `feather.json` also sets `hand_animation_on_swap: false` so tint rewrites don't
  bob the hand. The pack has no `custom_model_data` floats, no composite and no player-head models.
- Tint contract with SovereignGuns (every tint value V is 24-bit `0xRRGGBB`):
  `C = V >> 13` (11 bit): animation = `C / 160` (`ANIMATIONS` order), start game tick = `C % 160`
  (160 divides 24000, so the GameTime day wrap is seamless). `P = V & 0x1FFF`: colour
  `R4 = P >> 9`, `G5 = (P >> 4) & 31`, `B4 = P & 15`, decoded `(R4/15, G5/31, B4/15)`;
  `P == 0x0010` = transparent (discard). `colors[0]` is the gun tint (tintindex 0, only C matters);
  `colors[k]`, k = 1..704, is arm slot k (P = that skin texel's colour, same C as `colors[0]`).
- Playback (speed always 1x, no paused mode): `dt = mod(GameTime*24000 - start, 160)`, and
  `dt >= 150` counts as 0 (the client clock may trail the server's start tick); a loop plays
  `t = mod(dt, frames)`, a one-shot `t = min(dt, frames-1)`; the vsh interpolates between frames, so
  arms and gun move every rendered frame. The bake rejects animations over 140 frames. SovereignGuns
  re-anchors a looping animation's start by whole loops once 100 ticks have passed, so loops never
  reach the wrap.
- Skinned arms: the item atlas shader cannot read skins, so the arms are part of the sgvm model:
  three segments (`prfa_right_forearm`, `pla_left_arm`, `plfa_left_forearm`; the right upper arm is
  never on screen), base layer + sleeve layer (the base cube inflated 0.234375 px = 0.25 skin texel
  on every side). Each of the 6 faces of each layer is cut into its skin-texel grid (sides 4x6,
  caps 4x4); every texel is one quad with `tintindex` = its slot, bone = the segment, CCW outward.
  Vertex row 5th pixel r = 1 marks arm vertices. The vsh decodes P into a flat colour (`sgvmGun = 2`),
  the fsh discards alpha < 0.5 and lights it like the gun. 128 quads per segment layer, 768 per gun.
- Slots: the union of skin pixels of all texel quads sorted by (y, x), slot = index + 1 (704:
  right forearm 128 + right sleeve forearm 128 + left base 224 + left sleeve 224; identical for every
  gun, asserted). The bake writes the contract file `tools/generate/guns/objmc_arm_slots.json`
  (copy in `../SovereignGuns/src/main/resources/` when that checkout exists):
  `{"version": 1, "slots": [[x, y], ...], "sleeve": [bool per slot]}`. Skin mapping is vanilla's
  arm UV net with x/y negated (bone +x = player's right, +y = shoulder, -z = front), 64x64 classic
  arm (right base (40,16), right sleeve (40,32), left base (32,48), left sleeve (48,48)); upper
  segment side rows 20..25, forearm 26..31, caps rows 16..19 for both. Slim skins are not detected.
  `viewmodel_bake._selftest_uv` (runs in every gun script) re-derives every quad's pixel through
  vanilla's `ModelPart.Cube` polygons and asserts equality.
- Animation slots (`ANIMATIONS`, contract with SovereignGuns `ObjmcTime.ANIMATIONS`; control `C = anim*160 +
  start` must stay < 2048 so 12 is the maximum, asserted): 0 equip, 1 unequip, 2 standing, 3 sprint,
  4 aiming, 5 shoot, 6 aiming_shoot, 7 reload, 8 reload_fail, 9 inspect, 10 firearm, 11 scoped.
  `objmc_animations.json` uses these names.
- `reload` = the full sequence (the script's `reload_empty` if it has one, else its `reload`), resampled to
  exactly the WeaponMechanics `Reload_Duration`: frames = ticks + 1, `t_i = min(L, i * L / ticks)`, one-shot,
  json length = ticks/20. The ticks table `RELOAD_TICKS` in `viewmodel_bake.py` MUST match
  `plugins/WeaponMechanics/weapons/*.yml` `Reload_Duration` (ak47 57, g3 50, m14 65, ppsh41 104, uzi 25,
  m3 31, dragunov 70, ssg69 50, remington700 40); change both together. No `reload_empty` slot is baked.
- `reload_fail` (`GunModel.reload_fail`, called in every gun script, 1.2 s once): played when reload is pressed
  with no magazine item. Left hand leaves `support`, drops to an off-screen pouch point (reach-limited,
  below the view), pats twice, returns empty; the gun cants toward the camera and returns to the exact rest
  pose (tiny magazine nudge when the gun has a `magazine` bone). Arms are IK-solved like every animation.
- `scoped`: synthetic, 1 looping frame, every bone zero matrix (nothing of gun or arms is drawn) while a
  sniper scope overlay is shown.
- Scope overlay: `assets/sovereignmc/textures/misc/sniper_scope.png` (1280x720, generated by
  `tools/generate/guns/scope_overlay.py`) is an ordinary texture used as `minecraft:equippable`
  `camera_overlay` `sovereignmc:misc/sniper_scope`; the client stretches it over the screen ignoring aspect,
  so it is drawn for 16:9: opaque black outside a round view (92 % of the height) with a soft vignette and a
  thin mil-dot reticle (opaque lines, transparent elsewhere).
- Bullet projectile models (`tools/generate/guns/projectile_models.py`): WeaponMechanics shows a projectile as a
  packet-only invisible armor stand with the item on its head, yaw/pitch following the flight; in game the
  model's SOUTH (+Z) side is the direction of flight (verified: a -Z nose flew backwards). Item models `weapons:projectile/rifle`, `weapons:projectile/smg`,
  `weapons:projectile/pistol` (`assets/weapons/items/projectile/*.json` -> `models/projectile/*.json`, texture
  `weapons/textures/item/projectile/bullet.png` — item model textures must be under `textures/item/` or
  `textures/block/`, the only folders the block atlas loads, else they render as the missing texture;
  `head` display scale 1.2). WM config:
  `Projectile_Item_Or_Block: {Type: FEATHER, Item_Model: "weapons:projectile/rifle"}`.
- `feather.json` tints: index 0 default `(2*160) << 13` (standing, start 0); index k default the same
  | `P_default` = quantized `#B4846C` for base slots, `0x0010` (transparent) for sleeve slots.
- Check a shader edit against each client's includes with `glslangValidator` after expanding
  `#moj_import` from that version's `assets/minecraft/shaders/include/` (strip the includes' own
  `#version` lines; run `-S vert` / `-S frag`).
- Data textures stay lossless PNG; `height` is padded to a multiple of 16.

## BetterModel models

`bbmodels/*.bbmodel` are the source models. They are **not** converted by hand and the
BetterModel parsing/generation logic is **not** reimplemented here: the release workflow
runs the real BetterModel jar inside a throwaway Paper server, exactly as the plugin does
on a live server.

```bash
tools/generate/bettermodel/generate.sh                     # writes assets/bettermodel/ (gitignored)
JAVA_BIN=/path/to/java25 tools/generate/bettermodel/generate.sh
BETTERMODEL_VERSION=3.7.0 PAPER_VERSION=26.3 tools/generate/bettermodel/generate.sh
```

What the script does:

1. Copies every `bbmodels/*.bbmodel` into `plugins/BetterModel/models/` of a temporary
   Paper server.
2. Downloads the pinned BetterModel `paper` jar and a stable Paper build, then starts the
   server headless. BetterModel imports the models and writes its resource pack to
   `plugins/BetterModel/build/` during `ServerLoadEvent`. The script's config sets
   `module.player-animation: false`; first-person gun viewmodels are no longer BetterModel
   models (see "Gun viewmodel core shader").
3. Copies the generated `assets/bettermodel/` namespace into the pack root and stops the
   server. `pack.mcmeta`/`pack.png` from BetterModel are discarded; this pack keeps its own.

Requirements: Java 25+ and network access (Paper, BetterModel and its runtime libraries
are downloaded on every run). The server directory lives in a temp folder and is removed
afterwards; set `BETTERMODEL_KEEP_WORK=1` to inspect it.

Generated names are API for the server plugin: a model named `structure_smelter` produces
item models such as `bettermodel:model/structure_smelter_<bone>`
(`assets/bettermodel/items/model/structure_smelter_<bone>.json`), with
textures under `assets/bettermodel/textures/item/`, and model JSON under
`assets/bettermodel/models/model/`. Do not hand-edit `assets/bettermodel/`; edit the
`.bbmodel` and regenerate.

## Rendering text offline

`tools/render/render_text.py` draws a Minecraft text component with the client's font
metrics (pack-first resolution) and reports wrapped, clipped or missing glyphs. Read
`tools/render/render_text.md` for the full flag and metric reference. Requires `python3`
with Pillow and a client jar (or unpacked `assets/`) for `minecraft:default`:

```bash
python3 tools/render/render_text.py --client-jar ~/client.jar --self-test
python3 tools/render/render_text.py --client-jar ~/client.jar --json /tmp/dialog.json --width 0
```

`--self-test` must print `0 failure(s)`. Previews are written to `/tmp/text_render.png`
and are not committed.

## Gotchas

- `pack.sh` only resolves Argentum JSON; other namespaces can regress without CI noticing.
  Check their model/texture paths manually.
- `pack.mcmeta` mixes `supported_formats` with `min_format`/`max_format` (required while
  format 64 is supported, see "What this is"); test any format change in a real client
  before releasing.
- `pack.zip`, `ignored/`, `__pycache__/` and `build.sh` are gitignored. `pack.zip` must
  stay out of history.
- `*_offset_*` and `*_row_*` font variants are selected by name in plugin code. Adding a
  variant without adding it to the consuming code does nothing.
- Every asset path is case-sensitive in a zip and must remain a valid lowercase resource
  location.

## Cannons aim markers

- `sovereignmc:effect/muzzle_pointer`: one flat horizontal plane (`up`/`down` faces), local +Z = shot direction, local +Y = plane normal; the plugin rolls each segment around the path so the normal faces the gunner. One 32x32 tile (1 chevron) per segment; the plugin keeps segments about as long as the pointer is wide (1.5 blocks), so the chevron stays square. Verified in game: a chevron drawn toward texture +u points back at the gun, so the tile's tip is at -u (left). The `down` face uses `rotation: 270` so it agrees with the other faces.
- `sovereignmc:effect/landing_marker_1`, `_2`, `_3`: one vertical plane `[0,0,8]`-`[16,32,8]` with north and south faces (32x64 texture), for ItemDisplay with billboard VERTICAL. With transform NONE the model centre `[8,8,8]` sits at the entity, so the pole base is 0.5 block below it: the plugin must translate the display by `(0, +0.5, 0)` blocks at scale 1 (`0.5 * scale` otherwise). The pole (texture x=15..16) and ground ring are centred on the plane's centre line by construction, so billboarding does not swing the base.
